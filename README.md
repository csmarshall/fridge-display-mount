# fridge-display-mount

One display, one fridge, **three ways to hold up one plate**. A Waveshare 23.8 in FHD touch
monitor on the side panel of a Samsung RS23A500ASR counter-depth refrigerator, running a
household chore board. Parametric generators, validated cut files, and the sheets that explain
every decision, published at <https://csmarshall.github.io/fridge-display-mount/>.

Human-crafted and AI-assisted, human-directed: every dimension, constraint and trade-off here was
reviewed and decided by a human; the code was written with AI as a power tool.

| # | design | page | where in the repo |
|---|---|---|---|
| 1 | **The hook** — a bent plate over the fridge top, held flat by magnets. Finished, quoted, tagged `hook-final` | `hook.html` | repo root |
| 2 | **The clamped strut** — two slotted struts to the floor, clamped top and bottom, no magnets. Standalone fallback | `clamp.html` | `strut/` |
| 3 | **The hook, with optional strut** — design 1's plate cut thinner with four strut holes, so design 2's feet can be bolted on later without recutting. **Being ordered** | `index.html` | `strut/hybrid*.py`; the plate comes from the root generator |
| 4 | **The hook in stock aluminium** — hand-drilled. Validated, cheapest, and **rejected**: not a build the owner wants to do. Kept for the record | `angle.html` | `angle/` |

An engineer's guided read of designs 1 to 3, with the questions we want answered, is `review.html`.

`strut/` was its own repository until 2026-09-02 and was merged here with its history, because
design 3's plate is generated by the root generator and two repos meant two homes for one fact.

## The load path, in one line each

1. The arm **bears** on the fridge top and carries all the weight; the magnets only hold the
   plate flat.
2. The **floor** carries the weight; the clamps hold the struts in; nothing is fixed to the
   building, ever.
3. Design 1 as bought. If it proves too lively, two struts through the plate onto design 2's feet
   and lower clamp, and the magnets come off.

## Quick start

```bash
python3 -m venv .venv && .venv/bin/pip install ezdxf gmsh scikit-fem numpy scipy meshio
.venv/bin/python generate_bracket.py            # design 1: bracket_flat.dxf + preview + params
.venv/bin/python audit_dxf.py                   # acceptance test — run after EVERY generation
( cd strut && ../.venv/bin/python generate_hybrid.py )   # design 3's plate, via the root generator, audited
( cd angle && ../.venv/bin/python angle.py && ../.venv/bin/python angle_sheets.py )   # design 4: validate, templates, sheets
.venv/bin/python console_build.py               # index.html, hook.html, clamp.html, angle.html
.venv/bin/python review_build.py                # review.html, the guided read for an outside engineer
./publish.sh --check                            # everything above plus every sheet; pushes nothing
./publish.sh                                    # same, then push main and gh-pages
```

Every generator **validates before it writes** and exits non-zero having written nothing if any
check fails. That is deliberate: a silently-wrong cut file costs real money.

## What is here

| | |
|---|---|
| `generate_bracket.py` | design 1's generator. Formed dimensions in, flat pattern out. `--strut-bolts` adds design 3's holes |
| `audit_dxf.py` | independent acceptance test against any written DXF and its params JSON |
| `bracket_flat.dxf` | design 1's upload file — mm, layer 0, closed contours, one dashed bend line |
| `strut/dxf/H_hook_plate.dxf` | **design 3's upload file**, made by the root generator, audited |
| `strut/dxf/{A_clamp_bar,B_foot,C_plate,D_backing_strip}.dxf` | design 2's cut parts |
| `plate_fea.py` | finite-element plate check (gmsh + scikit-fem) of the body plate under a touch press |
| `console_build.py` | builds the three pages from one model — decisions, checklist, numbers, prices, every sheet |
| `publish.sh` | rebuild, validate, push `main` and the `gh-pages` branch GitHub Pages serves |
| `docs/` | design 1's brief, price study, review notes, vendor reference drawings |
| `strut/BRIEF.md`, `strut/reference/` | design 2's brief and its evidence (strut channel, SendCutSend PDFs) |
| `CLAUDE.md` | every design invariant, all three designs. Read it before changing anything |

Study scripts (`*_sweep.py`, `*_compare.py`, `*_explainer.py`, `*_study.py`) each answer one
question and write one SVG. `strut/clamp_sheets.py`, `strut/package.py` and
`strut/hybrid_sketch.py` do the same for designs 2 and 3; run them from inside `strut/`.

## House rules that bit us

- **No drifting constants.** If a value is derivable, derive it. Hardcoded numbers here have gone
  stale more than once — a magnet total, a detach table, a pad rule, a bend deduction — each time
  silently.
- **One home per fact.** The magnet height once appeared as 11.5, 12 and 13 mm on three drawings;
  the bend deduction lived in two repos with two values.
- **CLI flags may only turn things off.** `x = not args.no_x` silently overrode dataclass defaults
  and shipped duplicate holes into a cut file.
- **Render it and look at it.** Layout cannot be reasoned about.
