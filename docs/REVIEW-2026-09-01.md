## Gaps, ranked

### 1. The published page says the opposite of the current decision
`index.html` "What is being built": *"CURRENT — a clamped strut … there are NO MAGNETS … Work
continues in fridge-strut-mount."* Session state 2026-09-01: the hook is **primary again**, the
clamped strut is the fallback, and a third design (hook plate prepared for struts) is what will
be ordered. Neither `index.html` nor `archive.html` mentions the third design at all (grep for
third/hybrid/contingency: 0 hits in both). `hybrid_overview.svg` / `hybrid_sketch.svg` are
committed but not registered in `console_build.py`. `gh-pages` is at 08-31 18:23, one
decision behind.

### 2. The hybrid plate is 0.119 in, and the reason recorded for that is false in phase 1
`hybrid.py:41`: `plate_t = 0.119 * IN  # was .187 HRPO; the feet take load off the plate`.
The first order is the hook plate ALONE with no feet; the feet are bought only if the arm is too
lively. So in the configuration actually being ordered, a 0.119 in plate carries the full hook
load — the case the hook design settled on 0.187 in for (`thickness_study`, PRICE-STUDY: 0.14 mm
deflection, "feels rigid"). `hybrid.py` has **no stress or deflection check at all**; the hook
generator's neck/body SF checks were not carried over. Strength is almost certainly fine (SF
~25x by t² scaling from the 0.187 figures) but touch-press stiffness drops ~4x (t³) and nobody
has computed it. Either re-run the thickness reasoning at 0.119 and record the result, or go
back to 0.187 and re-quote.

### 3. The strut repo's cut files have no acceptance test
Five DXFs in `dxf/` and `audit_dxf.py` cannot run against any of them: it requires an
expectations JSON and none is written (`generate_parts.py` / `generate_hybrid.py` never emit
one; no `*.json` exists in the repo). BRIEF §5 lists `foot_params.json` and "audit_dxf.py …
needs re-pointing" as deliverables; neither happened. Session state's "audits clean" for
`H_hook_plate.dxf` was an ad-hoc run that cannot be repeated. This repo's own README says a
silently wrong cut file costs real money; the strut repo has exactly that exposure.

### 4. Four generator warnings nobody has acknowledged
`magnet_window_overlap`: all four body magnet discs overlap their vent window by **11.51 mm**
("the magnet face would sit over a hole"). Not mentioned in CLAUDE.md, the order doc, the BOM
or the page. Either it is accepted (magnet face bridges the window, foam still bears) and should
be written down as a decision, or the windows should move. The hook page currently shows the
part as validated without saying it carries warnings.
